Lesson 1 · GSAP in React

Fixing the services-chevron hover with useGSAP

Your ServicesNavDropdown component already rotates the chevron on hover — but the way it's wired is a classic GSAP-in-React anti-pattern. This lesson fixes it and gives you the rule to carry forward.

What your code does right now

In nav-dropdown.tsx, ServicesNavDropdown calls gsap.to() straight in the component body, gated by an if/else on open:

if (open) {
  gsap.to(servicesChevronRef.current, { rotate: 90, duration: 0.3, ease: "power2.out" });
} else {
  gsap.to(servicesChevronRef.current, { rotate: 0, duration: 0.3, ease: "power2.out" });
}

It works — the chevron does rotate — but three things are wrong:

1. It fires on every render, not just when open changes. Any unrelated re-render of this component (a prop change, a parent re-render) restarts the tween.
2. It runs outside GSAP's React context, so there's no automatic cleanup on unmount — GSAP even calls this pattern out by name.
3. It double-fires under React 18 Strict Mode in dev, because render bodies run twice. You likely haven't noticed because the two tweens animate to the same end state, but it's wasted work and a bug waiting to surprise you elsewhere.

The fix: useGSAP with a dependency array

GSAP's own React hook, useGSAP — which this file already imports but doesn't use here — exists exactly for this: it's useLayoutEffect plus automatic gsap.context() cleanup. Give it a dependency array like useEffect, and a scope so selector strings elsewhere in the tree can't accidentally match.

const rootRef = useRef<HTMLDivElement>(null);
const servicesChevronRef = useRef<HTMLSpanElement>(null);
const [open, setOpen] = useState(false);

useGSAP(() => {
  gsap.to(servicesChevronRef.current, {
    rotate: open ? 90 : 0,
    duration: 0.3,
    ease: "power2.out",
  });
}, { dependencies: [open], scope: rootRef });

Then attach rootRef to the outer <div className="relative">. Now the tween only re-runs when open actually flips, GSAP tracks and reverts it on unmount, and Strict Mode's double-invoke is handled correctly by the hook.

A related idiom you'll want soon: contextSafe

This fix uses a dependency array because the animation is driven by state (open). If you ever trigger a GSAP tween straight from an event handler — a raw onMouseEnter with no state involved — wrap that handler in contextSafe() instead, so it still gets tracked by the same context for cleanup:

const { contextSafe } = useGSAP({ scope: rootRef });

const onHoverIn = contextSafe(() => {
  gsap.to(".card", { scale: 1.1, duration: 0.3 });
});

Rule of thumb: animation driven by React state → dependency array. Animation fired directly from a DOM event → contextSafe. Your chevron case is the first kind.
